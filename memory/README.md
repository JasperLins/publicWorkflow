# memory/ — 记忆模块 v1.1

跨会话、跨子代理的持久记忆。目标:**新会话/子代理读四个数据文件即可恢复关键上下文**;文件系统即记忆,关键在分块限额与检索规则。

## 文件职责
| 文件 | 职责 | 恢复必读 |
|---|---|---|
| `project-profile.md` | 项目画像(概述/用户/价值/边界/假设),决策后修订 | ✅ |
| `decisions.md` | 双账本:①用户决策日志 D-xxx ②子代理工作假设账本 A-xxx | ✅ |
| `outputs-index.md` | 产出索引(含关键词)+ 阶段运行台账 + **唯一进度源** | ✅ |
| `backlog.md` | 待议池:超范围想法/功能的排队区 | — |
| `README.md` | 本文件 | — |

## 读写纪律
1. **会话开始**:读 profile + decisions + outputs-index。三文件均为空模板 = 新项目(阶段 0 初始化 = 清除示例行原地启用);任一非空 = 恢复,**进度只看 outputs-index**,冲突向用户确认。
2. **子代理启动**:只注入 `project-profile.md` 全文 + 任务相关文档头;需细节时按 outputs-index 检索:**先按「阶段」列过滤,再按「关键词」列匹配,命中后读原文**。
3. **写入时机**:用户选择 → 立即写 decisions.md;子代理回传假设 → 登记假设账本;文档落盘 → 立即登记 outputs-index;超范围想法 → 入 backlog.md。
4. **决策摘要判据**(profile):仅「改变范围边界/目标用户/商业模式」的决策才入画像摘要,其余留在 decisions.md。
5. 状态「草稿」→「已确认」唯一途径:用户在批量提问或书面回复中确认。

## decisions.md 登记细则
- 用户决策:**1 题 1 行**;「用户选择」列写**结论文本**(如「A 轻量计算器先行」),不写「Q2 选 A」;「阶段」列受控取值:`阶段 N` 或 `阶段 N 复盘`(N=0–8)。
- 假设账本(A-xxx):字段 = 编号/日期/声明角色/假设内容/影响文档/状态(生效|已被 D-xxx 取代)。子代理回传摘要**必须**含「本次假设清单」;主代理登记;启动下游时注入相关假设;用户否决 → 转决策流程处理并更新状态。

## 分块限额(防膨胀,按节独立触发,不等整文件)
| 文件/节 | 上限 |
|---|---|
| profile 每要素(概述/用户/价值) | ≤5 行 |
| profile 范围做/不做 | 各 ≤10 行 |
| profile 关键假设 | ≤15 行(每条一行+置信度) |
| decisions 单条 | ≤3 行(被否决选项压缩为「问题→结论」一行) |
| outputs-index 单条登记 | ≤3 行 |

## 蒸馏规则(双触发)
- **写入时顺手压缩**:追加新决策时,同主题旧决策压缩为一行结论;假设被决策取代时立即标状态而非新增。
- **阶段末例行蒸馏**,按序执行:① 删过程细节,改写为「结论 + 见 docs/xxx」指针;② 合并同主题条目;③ 校验 D-xxx / A-xxx 编号连续;④ 复核用户最终选择一条未丢(decisions 蒸馏**永不删除最终选择**);⑤ 任一节超限单独蒸馏该节。
