# Skill: quotation-calculator — 行情锚定报价

> v1.2 变更(依据委托方实测反馈 TODO-1/2):定价主逻辑从「人日成本累计×利润率」改为**品类行情锚定 + 功能难度交叉 + 成本下限校验**三法;token 默认包月口径不计价;承认行情竞争下利润可能很薄,如实呈现。

## 输入依赖
- `docs/03-requirements/feature-list.md`(功能与难度依据)、`docs/06-ai-plan/ai-dev-plan.md`(周期与人力实际投入)
- `docs/04-tech/third-party-services.md`(第三方费用结论,含服务器)
- **`skills/quotation-calculator/references/market-benchmarks.md`(必读:品类行情基准表,每项目须核价更新)**

## 定价三法(按序执行)

### ① 品类行情锚定法(主定价)
- 判定品类(小程序 / Web / App / 管理端组合…)× 规模档(模板级 / 标准 / 复杂),从行情基准表取价格区间。
- 行情表数据为低置信锚点:**必须先联网核价或引用委托方提供的当期行情**,在文档中写明来源与日期;委托方给的锚点优先。

### ② 功能难度交叉法(区间校验)
- 难度分 = Σ(P0 子任务数×3 + P1 子任务数×1)× 难度系数。
- 难度系数(叠加取乘积,封顶 2.5):AI 能力集成 1.3–1.5 / 支付交易 1.2 / 实时通信 1.2–1.4 / 多端 1.5 / 硬件对接 1.5+ / 纯信息展示 CRUD 1.0。
- 由难度分映射报价区间,与①的行情区间交叉取交集或说明偏离理由。

### ③ 成本下限校验(底价红线)
- AI 实际成本 = 精简人力(开发+测试+评审实际人日 × 单价)+ 第三方开发期费用 + 内容采购;**token 默认按包月 code plan 口径计 ¥0**(仅当委托方声明按量 API 时才折现)。
- **报价 ≥ 底价 × 1.2**(红线);低于红线的报价要么砍范围要么如实提示亏本接单风险。
- **贴线处置**:行情中位与红线重叠/倒挂时,推荐档 = max(行情中位, 红线) 并在文档中如实标注「贴线定价」及理由,不静默抬价。

## 执行流程
1. 按①得行情区间 → 按②交叉校验 → 按③验证底价红线。
2. **报价三档**:行情下限 / 中位 / 上限(替代旧「利润三档」);推荐档标理由;**利润额 = 报价 − 实际成本,如实呈现**(行情内卷时利润薄是常态,不粉饰)。
3. 生成 `docs/07-business/cost-profit.md`(内部版:成本归集 + 三法推导过程 + 三档报价 + 利润额 + 敏感性)。
4. 生成 `docs/07-business/quotation.md`(甲方版:**严禁内部数字/零注释**;分模块包干价 + 行情依据一句;人天口径仅当甲方要求时并列且用市场计费价;付款里程碑建议 30-40-30;交付物/不含项/资产归属/保修期)。
5. 敏感性:范围 ±20%、周期延误 2 周(延误成本=人力维持率 30%×延误人日×单价)。

## 补充规则
- 双基线分离:成本基线(AI 实际投入)与定价基线(市场行情)分开呈现,不得混算。
- 甲方版零注释:内部备忘只写 cost-profit.md 与 questions 文件。
- 年费制服务按「周期天数÷365×年费」折入开发期;运营期按量费用归甲方(权责切割,报价不含)。

## 质量自检清单
- [ ] 行情区间有来源(基准表 or 当期核价 or 委托方锚点)与日期
- [ ] 三法推导过程可复算,报价 ≥ 底价×1.2
- [ ] 三档报价 + 推荐理由 + 利润额如实(允许薄利/负利提示)
- [ ] token 按包月口径 ¥0(或注明按量声明来源)
- [ ] 报价单可直接发甲方(无内部数字、零注释)
- [ ] 敏感性三情景齐全
