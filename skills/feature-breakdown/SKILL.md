# Skill: feature-breakdown — 功能清单与工时估算

> v1.1 变更:工时口径改为「初估值,待阶段 4 校准」并支持回填二次执行;汇总表端别占比适配纯移动端/无后端项目;问题清单统一落盘。

## 输入依赖
- `docs/03-requirements/requirement-doc.md`(必需,缺失即阻塞)
- 阶段 3 初次执行:**不得依赖** `docs/04-tech/tech-stack.md`(尚未产出),按通用口径估算并声明误差 ±20%。
- 阶段 4 回填执行:输入含 `tech-stack.md`,按选型逐项校准,变更记入功能清单「变更记录」。

## 执行流程
1. 逐条评审需求:技术可行性(可行/需预研/不可行),不可行或含糊处列入 questions-stageN.md。
2. 拆解:模块 → 功能 → 子任务,颗粒度 0.5–3 人日/子任务;每子任务标注依赖与「适合 AI 并行」(供 ai-dev-estimator)。
3. 优先级:继承需求 P0/P1/P2;跨需求依赖显式标注,无环。
4. 工时(初次):每子任务「开发+自测」人日 → 小计 → **× 缓冲系数 1.4** → 总计;文档显著位置注明「⏳ 初估值,待阶段 4 技术栈定稿后回填校准,当前误差 ±20%」。
5. 工时(回填,阶段 4):按技术栈重估受影响子任务;变更(子任务/增删/人日)写入「变更记录」表(日期/变更项/原因);总偏差 >±20% 上报项目经理列入批量提问。
6. 风险:每条「风险 → 影响 → 缓解 → 备选」。
7. 汇总表:P0/P1/P2 小计、直接合计、含缓冲合计、**层别占比(按项目形态填写:前端/后端/移动端/设计等,不适用的层写「不适用」)**。

## 产出要求
- 路径:`docs/03-requirements/feature-list.md`,模板 `templates/feature-list.md`,含文档头契约节。

## 投入缩放
- **轻量**:功能 ≤10 条 → 子任务表一次成型。
- **标准**:10–30 条 → 按模块分小节,先 P0 后 P1/P2。
- **深度**:>30 条或含预研项 → 增列「预研清单」单独估算,预研结论可推翻初估。

## 质量自检清单
- [ ] 子任务 0.5–3 人日,无黑盒大块;依赖无环
- [ ] 总工时含缓冲系数且写明数值;初估/回填口径已标注
- [ ] 需求 ID 双向可溯(需求→子任务全覆盖,子任务→需求可回指)
- [ ] 未确认功能(待议池/风险建议)未混入工时表
- [ ] 层别占比适配项目形态
