# Skill: doc-quality-reviewer — 文档质量审查与门禁预检

> v1.1 变更:新增「门禁预检模式」;审查维度加入记忆一致性与文档头契约检查。

## 两种使用模式
1. **阶段质审模式**(默认):对该阶段全部产出做三维审查,出报告 `docs/<阶段目录>/review-<阶段号>.md`。
2. **门禁预检模式**(workflow 门禁阶段调用):按 `workflow/README.md` 该阶段「完成标准」逐条自检 → 不合格项**就地修复一轮**(上限 1 轮)→ 出一行结论「预检通过/修复 N 项后通过」;此时可豁免独立报告,结论按以下标准格式写入 questions-stageN.md 头部(**勿删该行,只更新其内容**):
   `> **门禁预检(主代理/QA 执行,{日期})**:… → **{预检通过|修复 N 项后通过}**`

## 执行流程
1. **完整性**:对照模板/SKILL 结构逐字段查缺;「📌 文档头契约」节是否已填且 ≤5 条结论;质量自检清单是否真执行过。
2. **一致性(跨文档)**:
   - 数字口径:工时、成本、界面数、周期在 需求/技术/AI 计划/报价 间一致;
   - 范围口径:需求「不做清单」vs 功能清单 vs 界面清单 vs 待议池(backlog.md)无冲突;
   - 决策口径:`memory/decisions.md` 用户选择在所有文档落实;假设账本(A-xxx)中影响本文档的假设已显式引用;
   - 记忆一致性:outputs-index 登记齐全、进度正确、D-xxx 编号连续。
3. **可开发性**:抽 3–5 条 P0 需求,以「新接手工程师」视角判断能否直接开工;卡点即缺口。
4. **输出**:按「缺口 → 位置(文件:章节)→ 严重度(阻塞/建议)→ 修复建议(具体到改法)」列表;末尾一行结论:「可过门禁 / 需修复 N 项后过门禁」。
5. 只提建议不重写;修复由原角色或项目经理执行。

## 质量自检清单
- [ ] 三维(完整/一致/可开发)+ 记忆一致性均覆盖
- [ ] 每个缺口有具体位置与修复建议;阻塞/建议分级明确
- [ ] 有明确「能否过门禁」结论
- [ ] 门禁预检模式下:修复不超过 1 轮,结论已写入 questions 文件头部
