# Skill: ai-dev-estimator — AI 开发周期与 token 预估

## 目标
回答:用 AI 代理开发这个项目要多久、烧多少 token、产出多少代码,与传统开发相比提效多少。

## 执行流程
1. **任务包拆分**:按功能清单把子任务组装为 AI 可执行的任务包(每包一个可验收交付物,如「用户模块:注册/登录/资料」);标注依赖顺序与可并行组。
2. **排期**:批次划分 → 每批预计日历天(含人工评审、联调、修复);汇总总周期与关键路径。
3. **token 预估(三档:乐观/中性/保守)**:
   - 每批次估算:输入 token(上下文+原型/文档注入)× 会话轮次 + 输出 token(预计代码量)。
   - 产出比:预计「输入 token : 输出有效代码行/千 token」比例;引用 `memory/outputs-index.md` 中前期各阶段的实际 token 记录做校准。
   - 汇总全程 token 总量,按单价假设(注明模型与单价、币种、日期)折算费用。
4. **人机分工**:每批次标注 AI 独立 / AI 起草+人工评审 / 人工主导,并说明 UI 静态原型如何作为复现基准(对照 `./UI/` 实现)。
5. **质量门禁**:每批次验收标准(编译/构建通过、自测用例通过、与原型一致性检查)。
6. **对比**:与传统开发(功能清单人日)对比,给出提效倍数与前提条件(需人工投入不减的部分要诚实列出)。

## 产出要求
- 路径:`docs/06-ai-plan/ai-dev-plan.md`,使用模板 `templates/ai-dev-plan.md`(含 token 三档表)。

## 质量自检清单
- [ ] 每个任务包有验收标准与并行组标注
- [ ] 周期含人工评审时间,非纯 AI 执行时间
- [ ] token 三档表含单价假设与计算式
- [ ] 提效对比列出人工投入不变的部分
