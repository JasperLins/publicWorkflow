# Skill: ux-flow-designer — UX 流程与信息架构

> v1.1 变更:界面清单增加「主态/组件规格态」区分与图标建议列,消除静态原型二义性;字号规范统一 px;输入依赖声明。

## 输入依赖
- `docs/03-requirements/requirement-doc.md` + `feature-list.md`(必需,缺失即阻塞——界面范围来自功能范围)
- `memory/project-profile.md`

## 执行流程
1. **Persona**:1–3 个目标用户画像(身份/场景/核心诉求/技术熟练度)。
2. **用户旅程图**:每 Persona 一条核心旅程:目标 → 触点 → 动作 → 情绪 → 痛点 → 机会点。
3. **信息架构**:页面/模块树(≤3 层) + 导航模式结论(底部 Tab / 侧边栏 / 顶部导航)。
4. **关键任务流程**:注册登录(**如适用**——无账号架构可依据决策裁剪并注明)、核心使用闭环、支付(如有),mermaid 表达,**覆盖正常路径 + 主要异常路径**(失败/空态/额度用尽等)。
5. **界面清单**(核心交付):每屏一行——编号(S1…)、文件名(kebab-case,与 app-ui-design 产出对应)、名称、目的、关键元素、**主态说明 + 组件规格态(空态/无结果等次要状态,允许原型以标注区块并列呈现)**、TabBar/导航图标建议、对应需求 ID、优先级;数量必须与功能清单对齐,超出部分标注来源。**无界面的 FR(如系统能力类)用「需求映射表」交代去向,不得静默遗漏**。
6. **交互原则**:反馈(加载/成功/失败三态)、手势/快捷操作、可访问性底线(字号/对比度)。

## 产出要求
- 路径:`docs/05-uiux/ux-flows.md`,模板 `templates/ui-ux-spec.md` 第 1–5 节,**字号一律用 px**(下游 HTML 直接等值使用)。

## 质量自检清单
- [ ] 每个 P0 用户目标有完整闭环流程(含异常路径)
- [ ] 信息架构 ≤3 层且有导航模式结论
- [ ] 界面清单逐屏对应需求 ID;文件名 kebab-case
- [ ] 每屏区分主态/组件规格态;含图标建议
- [ ] 交互原则覆盖加载/成功/失败三态;字号单位为 px
