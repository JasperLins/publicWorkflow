# Skill: requirements-organizer — 需求整理

> v1.1 变更:新增输入完备性检查(缺失上游记欠账并指定回填阶段);需求来源枚举增加「项目画像」;功能需求表「用户故事」列填 US-ID;问题清单统一落盘 questions-stageN.md。

## 输入依赖与完备性检查(第 0 步,必做)
逐项检查,缺失时**显式记入产出文档「未决问题」节并指定回填阶段**,不得静默跳过或虚构:
| 输入 | 缺失时处理 |
|---|---|
| `docs/01-brainstorm/ideas.md` | 阻塞 → 报告项目经理 |
| `docs/02-market/feasibility.md`(阶段 2 产物) | 非阻塞 → PRD 第 1 节标注「⏳ 欠账:待阶段 2 补市场依据」,列入 questions-stage3.md |
| `memory/decisions.md` 用户决策 | 非阻塞 → 未决策项列入 questions-stage3.md |
| `memory/backlog.md` 待议池 | 池内条目不得进入需求,除非用户已在批量提问中确认采纳 |

## 执行流程
1. 汇总输入:头脑风暴推荐方向、可行性结论、用户已确认决策。
2. 用户故事:格式「作为<角色>,我要<动作>,以便<价值>」;P0 需求必须覆盖一条完整用户价值闭环。
3. 功能需求:每条含 ID、描述、用户故事(**填 US-xx 编号**)、优先级(P0/P1/P2)、验收标准(Given-When-Then 或一句可验证标准)。
4. 非功能需求:性能、安全、合规、兼容范围。
5. **范围边界**:本期不做清单(防蔓延);待议池条目保持池内,不写入。
6. 需求来源标注,枚举:**用户原始想法 / 市场分析 / 竞品差异化 / 用户决策(D-xx)/ 项目画像**(画像演绎出的细化需求标「项目画像」)。
7. 遗留含糊点整理为 `docs/03-requirements/questions-stage3.md`(批量提问格式,每题含推荐项与回退项);模板内不再内嵌问题节。

## 产出要求
- 路径:`docs/03-requirements/requirement-doc.md`,模板 `templates/requirement-doc.md`,含「📌 文档头契约」节。

## 质量自检清单
- [ ] 输入完备性检查已执行,欠账已显式标注并指定回填阶段
- [ ] 每条功能需求有 ID、US-xx、优先级、验收标准
- [ ] 范围边界(不做清单)明确;待议池条目未混入
- [ ] 需求来源可追溯(五种枚举),无凭空需求
- [ ] 无歧义词(「尽量」「可能」「支持大量」)
