## 📌 文档头契约(下游先读这节)
- **关键结论**(≤5 条):
  1. 产品定位:面向 25–40 岁城市家庭买菜主力的 iOS 食材管家,P0 = 一条完整价值闭环「整拍 10 秒录入 → 临期提醒 → 现存食材菜谱推荐 → 做菜一键消耗」(D-002/D-006)。
  2. 优先级分布:P0 ×10(闭环本体 + 免费额度护栏)、P1 ×3(订阅 IAP/购物速览/Onboarding)、P2 ×1(菜谱筛选器),共 14 条 FR;兑现 D-006「整拍录入 > 闭环 > 免费结构」。
  3. 范围边界一句话:本期不做 Android/Web、生鲜电商、多人共享(BL-002)、社区 UGC、小票 OCR(BL-001)、节省统计报告;BL-003 条码、BL-004 购物清单保持待议池,**未裁决前不进入任何优先级**(questions-stage3.md Q1/Q2)。
  4. 差异化兑现 D-004:不拼功能数——竞品 14 项矩阵中我方只做「三支柱」相关项,条码/清单/共享/统计全部留池或排除。
  5. 硬门槛:录入全链路 ≤10 秒(#8 红线)、识别 Top-3 准确率 ≥85%(D-009 双指标之一,口径见 A-017)。
- **关键假设与置信度**:A-012~A-018(见第 6 节);最高风险 = 识别准确率与云端 API 成本(中置信)。
- **可引用承诺**:FR-01~FR-14、US-01~US-08、优先级分布(P0×10/P1×3/P2×1),可供功能清单/UX/报价直接引用。
- **未决问题**:见 `questions-stage3.md`(共 8 题,含 BL-003/004 裁决)。

## 1. 项目概述
- 一句话定位:「冰箱食材管家」iOS App——拍照/手动录入食材,自动跟踪保质期并临期提醒,基于现存食材推荐菜谱,减少家庭食物浪费(项目画像)。
- 背景与机会:
  - 头脑风暴(ideas.md):方向 A「拍照 AI 识别 + 临期提醒 + 菜谱推荐」总分 9 进入 MVP(D-002);#8 确立「录入 ≤10 秒」红线。
  - 市场可行性(feasibility.md 结论):「调整后做」(中置信)——TAM ¥75–150 亿/年、SOM 中值 ¥272 万/年(D-008);每户每年浪费价值约 ¥200–950;供需缺口 =「零录入负担的库存 + 临期提醒 + 按现存食材推荐菜谱」的闭环无人做好。
  - 竞品(competitor-analysis.md):最强直接竞品「有菜」与我方方向高度重合,窗口在「10 秒体验打磨 + 闭环质量」(D-004);差异化三机会 D-2B-1/2/3 全采纳(D-006)。
- 目标用户与核心价值:25–40 岁城市家庭买菜主力(双职工为主,次要独居青年);核心价值 = 录入 10 秒、不再因遗忘导致食材过期,每年省下数百至数千元食物浪费(画像)。

## 4. 非功能需求
- 性能:录入全链路(快门→入库确认)≤10 秒(#8);识别 API 往返 P95 ≤3 秒;首页冷启动 ≤2 秒;库存 ≤500 条时列表滚动不掉帧。
- 质量硬指标:识别 Top-3 准确率 ≥85%(D-009;口径细化见 A-017);上线后 4 周留存 ≥25%(D-009,运营验证指标,非开发验收)。
- 安全与合规:无账号体系(A-012,待 Q5 确认)下不收集个人身份信息;食材照片仅用于识别,上传行为在隐私政策中明示(PIPL);IAP 走 Apple 官方通道;本地数据提供 iCloud 备份开关。
- 兼容范围:iOS 16+(A-013,待 Q7 确认);iPhone 全尺寸为主,iPad 兼容显示(不做专属布局);中文(简体)单语言。
- 可靠性:临期提醒依赖本地推送,无网络仍按期触发;识别失败可无损降级到手动录入(FR-04)。
